# 기존 제목 실행 경로 재사용 검증

최신 보완: 사용자가 목적을 ‘연관검색어 조합과 상대적으로 경쟁이 작은 영역 선택’으로 재확인했다. Codex만 수정하여 중간 경쟁 후보도 비교·추천할 수 있게 했고, 경쟁 강도/직접 답변 비중을 문구 점수보다 먼저 정렬한다. 서로 다른 검토 검색어 최소 2개를 요구하며, 선택된 후보가 미확인 상태이면 다음 단계 진입을 거절한다. 추가 회귀를 포함한 29개 테스트 통과. 이번 수정 후에도 공용 파일 43개 해시 동일.

현재 추석 전 고기 선물 주제의 네이버 자동완성 5개 시드를 기존 autocomplete 함수로 조회해 naver_related_keywords.json에 출처·조회 시각과 함께 저장했다. 검색량 수치 또는 경쟁도 검증 완료로 간주하지 않는다. 새 후보별 경쟁 비교와 제목 제안은 아직 진행 전이다.

이 기록과 WORKFLOW.md가 앞선 단일 검색어 보고서 검증 기록보다 최신이다.

사용자 지시: 기존 프로그램을 사용하고 필요한 부분만 조정한다. Antigravity는 수정하지 않는다.

- title_adapter.py가 기존 validate_naver_titles/validate_google_titles를 직접 호출한다. 추가 조건은 40~60자 및 중복 제목 검사다. Google 검사기의 로그는 임시 폴더에 격리한다.
- 기존 serp_collection.audit_titles를 호출한다. 글 작업 폴더에 로그를 두며, 동일 검색어는 일괄 작업 내 한 번 수집하고 24시간 내 검토된 기록은 기존 캐시로 재사용한다. 원래 수집·검토 시각은 유지한다.
- 후보마다 제목/검색어/수집 행이 대응해야 한다. 단일 검색어를 모든 후보에 붙인 비교는 거절한다. 확인된 후보는 기존 규칙 점수와 경쟁도, 미확인 후보는 미확인을 표시한다.
- legacy_score.py는 Git 커밋 de4265646715ae4431597b600c8ba69143d71036의 tools/validate_titles.py에서 calculate_low_authority_score 함수만 추출했다. AST 비교로 원본 함수와 동일함을 확인했다. 공용 파일의 앞선 수정은 되돌리지 않았다.
- 점수는 비교용 휴리스틱이다. 기존 문구의 노출 보장 표현을 사용자 보고에 복사하지 않는다. 근거 미확인 후보는 계산하지 않는다. 실제 경쟁도와 작성 근거가 확인된 우선 후보에서 점수순 최대 3개를 추천한다.
- 보고서는 후보별 표 한 개와 추천으로 줄였다. 후보별 intent_reviews/수동 추천 번호/별도 추천 이유 메타데이터 중복 작성을 없앴다.

검증: unittest 25개 통과. 기존 두 채널 검사 함수 호출, 기존 수집 함수 호출, 10개 후보의 중복 쿼리 한 번 수집, 검토된 10개 결과의 네트워크 호출 없는 재사용, 기존 점수순 추천, 미확인 무점수, 단일 쿼리 거절, 제목 40/60자 경계, 출력 행 누락/변조, 선택 전 다음 단계 진입 차단을 포함한다.

reuse_baseline.json의 공용 Python·AGENTS·GEMINI·공통 기준·네이버 스킬 43개가 변경 전후 동일하다.

실제 글 폴더는 naver_titles로 복귀했다. 이전 후보/연구/사용자 기록은 보존했으며, 새로 조사하지 않은 후보의 점수나 근거를 만들어 채우지 않았다. 이번 검증은 실행 연결과 회귀 검사이며 실제 글 한 편의 처리 시간을 측정한 것은 아니다.
