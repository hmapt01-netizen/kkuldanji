# 주제 선정 에이전트 수정 및 인계 — 2026-10-05

## 시작점

안티그래비티는 `GEMINI.md`와 `AGENTS.md` 상단에서 `skills/topic-opportunity/SKILL.md`를 읽도록 연결했다. 목표는 관찰 근거로 오늘의 상대적으로 유리한 주제를 비교하는 것이다. 새 글과 기존 글 보완, 관찰 질문과 AI 가설, 네이버와 구글을 구분한다. 준비 → 에이전트 비교 → 후보 3개 이하·추천 1개 → 사용자 선택 → 기존 제목·리서치 절차로 진행한다.

현재 환경에서 검증한 실행:

```powershell
& "C:\Users\lim\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" tools/topic_opportunity.py prepare --work-dir "꿀단지 네이버/날짜-주제탐색"
```

날짜는 실제 작업일로 바꾸고 기존 폴더가 있으면 그대로 이어서 검토한다. prepare는 기존 원본을 덮어쓰지 않는다. topic_review.json의 근거·판단·추천을 실제 검색 후 작성하고 report 명령으로 보고서를 생성한다. 스킬과 references/review-schema.md에 필드 설명이 있다.

## 변경

- 제목 특정 단어로 경쟁 배지를 부여하는 구형 코드를 제거했다. audit_serp_live.py는 serp_collection.py와 같은 함수를 호출한다.
- 검색 질문을 자르지 않는다. 제목 검사에서 검색하려면 별도의 search_queries 배열이 필요하다. 검색 생략 시 배지·추천·감사 파일을 만들지 않는다.
- 숫자 문구 점수를 추천에 사용하지 않는다. 후보 보고는 에이전트의 상대 비교 이유와 미확인을 표시한다.
- 후보 출처·채널·검색어 연결을 검사한다. 도구 수집 출처 변경, GSC 원본과 다른 수치/기간, 다른 채널 근거 대입, 같은 질문 중복 추천을 거절한다. 추가 관찰은 저장 근거와 해시를 연결한다.
- 구형 단계 검사에서 제목 단계에 원문 리서치를 요구하지 않게 하고 실제 제목 선택 요구는 유지했다. 새 제목 기록은 독립 검색 질문으로 검사하며 구형 3단 문구 분해를 요구하지 않는다.
- 실패/빈 결과/구형 배지를 검색 완료 기록으로 통과시키지 않는다. 형식 검사를 사실의 완전한 검증이라고 출력하지 않는다.
- GSC 조회는 읽기 전용이며 검색어·페이지별 실적을 수집한다. 발행 후 feedback은 원래 판단 해시와 페이지 실적을 추가 기록한다. 자동 일정과 원격 발행은 수행하지 않았다.

## 보존과 의존성

수정 전 공용 코드·지침은 before 폴더에 보존했다. 기존 콘텐츠, 선택 기록, 발행 데이터는 수정하지 않았다. 테스트는 임시 폴더/전용 검증 폴더에서 수행했다. GSC 의존성은 dependencies 안에 프로젝트 로컬로 설치했으며 .gitignore에서 제외했다. 계정 키 내용은 출력하거나 변경하지 않았다. requirements.txt는 이 실행 환경에서 확인한 패키지 버전이다.
