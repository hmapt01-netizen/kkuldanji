# Codex 실행 함수 내부 단계 검사

사용자 요청: 규칙 문서에만 두지 말고 기존 Antigravity처럼 Python 실행 경로 안에서 선행 단계를 검사한다. Antigravity 원본은 수정하지 않는다.

변경:

- title_adapter CLI와 collect 함수에서 실행 단계, 실제 연관검색어 자료, 제목의 검색어 보존을 확인한 뒤 기존 검색 수집기를 호출한다.
- report_guard의 build_report에서 단계/후보별 근거를 확인한 뒤 파일을 쓴다. check 명령을 따로 실행하지 않아도 선행 검사가 적용된다.
- 제목 완료 기록에는 related_keywords.json도 필수이며, 내용 변경은 해시 검사로 감지한다.
- register_post.py는 제목 선택·이미지 승인 및 선택한 구글 제목과 등록 제목 일치를 먼저 확인한 뒤 기존 add_post를 호출한다. 기존 step_guard/image_guard/참고문헌/빌드 검사는 유지한다. 원본 파일은 그대로 두고 실행 중 작업 폴더 선택만 명시된 폴더로 연결한 뒤 복원한다.

검증:

- 오프라인 회귀 테스트 38개 통과. 선행 단계 누락 시 수집 함수 미호출, 보고서 미생성, 등록 함수 미호출을 검증했다.
- 유효한 이미지 승인 이후에만 기존 등록 함수가 호출되는 분기를 모의 함수로 검증했다. 실제 글 등록·DB 수정·사이트 빌드는 수행하지 않았다.
- 실제 현재 작업은 naver_selection 대기다. 구글 보고서 생성과 등록 CLI가 종료 코드 2 및 복귀 단계 naver_selection으로 차단됨을 확인했다. 네이버 전체 보고서 finish는 통과한다.
- 공용 파일 43개는 변경 전후 해시 동일하다.

범위: Codex 지정 Python 진입점과 함수에서의 실행 차단이다. 임의의 외부 프로그램·직접 파일 쓰기·채팅 전송·이미지 도구 호출까지 금지하는 OS/앱 보안 장치는 아니다. 기존 실행 경로를 우회하지 않도록 Codex 운영 규칙에도 지정 진입점을 명시했다.
