## 원문 열람은 리서치에서만 (2026-09-16 최종 사용자 지시)

이 절은 아래의 이전 단계 순서·본문 실사 요구보다 우선한다.
- 순서: 주제 후보·선택 → 네이버 제목·선택 → 구글 제목·선택 → 리서치 → 작성. 주제와 제목 단계에는 제목·검색 화면 요약만 본다. 기존 글 본문, 경쟁 글, 공식 원문을 절대 열람하지 않는다.
- 원문은 리서치 단계에서만 읽는다. 작성·이미지·검수 단계에는 리서치에서 작성한 source_notes.md와 자체 원고를 사용한다. 추가 원문이 필요하면 사유를 기록하고 리서치로 전환한 뒤 확인한다. 운영 규칙과 Python 소스의 유지보수는 콘텐츠 원문 열람에 해당하지 않는다.
- codex_tools/source_access_guard.py --work-dir 작업폴더 status로 상태를 확인한다. transition --phase titles --note 실제주제선택, 이후 transition --phase research --note 실제선택발언 --naver-title 확정제목 --google-title 확정제목으로 이동한다. 선택 발언을 만들지 않는다. 조사 완료 후 transition --phase writing --note 조사완료로 닫는다.
- 원문을 열기 직전에 이 도구의 check --resource URL또는경로를 실행한다. Python으로 읽을 때는 read --resource를 사용한다. 거절되면 브라우저·검색 도구·다른 명령으로 대신 열지 않는다. 웹 검색의 제목·요약 확인은 원문 열람과 구분한다.
- 도구는 단계와 허용·차단 내역을 source_access_state.json 및 source_access_log.jsonl에 기록한다. 연결된 read 실행은 리서치 외 단계에서 파일·네트워크 읽기 전에 차단한다. 도구 밖의 브라우저나 임의 명령을 OS 수준에서 감시하는 기능은 없으므로 에이전트도 반드시 사전 check를 지킨다.
- workflow_guard 제목 단계는 본문 실사·공식 출처를 선행 요구하지 않고 제목 형식을 검사한다. 경쟁 평가는 제목 기준 잠정 판단으로 표시한다. 이전 완료 기록은 새 순서에 맞춰 자동 조작하지 않는다. 기존 작업은 선택 발언과 산출물을 보존하고 새 순서로 재검증한다.


## 본문 가독성과 출처 표시 (사용자 최신 지시)

이 절은 기존 명언·출처 주어·도입부 확인 날짜 의무보다 우선한다. 구글·네이버 본문은 독자의 질문에 대한 결론과 행동을 먼저 제시한다. 조사 과정을 설명하거나 기관명·문헌명·확인 날짜를 반복해 분량을 늘리지 않는다. 고정 예시문으로 문체를 제한하지 않는다.

- 상단 카드는 직접 작성한 핵심 요약으로 구성할 수 있다. 명언이나 기관 인용을 필수로 넣지 않는다. 직접 작성한 요약을 인용문 또는 기관의 발언처럼 표시하지 않는다. 요약은 div 또는 section을 사용하며 기존 카드 디자인을 유지한다.
- 일반적인 근거는 하단 참고 문헌에 모은다. 특정 연구 결과·직접 인용·기관별 기준 차이처럼 독자의 이해에 필요한 경우에만 본문에 출처를 짧게 밝힌다. 모든 수치 앞에 기관명을 붙이는 규칙은 적용하지 않는다.
- 조회일과 유효성 검토는 조사 기록에 보존한다. 자료의 기준일 자체가 독자의 판단에 영향을 줄 때만 본문에 표시한다. '요지'와 조사 확인 시점을 도입부의 상투 문구로 붙이지 않는다.
- 의학적 조건·예외와 근거 검증은 유지한다. 출처 문구 반복으로 애드센스 승인이나 검색 점수가 좋아진다고 단정하지 않는다. 필요한 설명을 마쳤다면 기존 분량을 채우기 위해 문장을 덧붙이지 않는다.

## 작업 저장 위치와 본문 미리보기 (2026-09-15 사용자 지시)

신규 콘텐츠의 조사·초안·이미지·검사 기록은 `D:/작업/꿀단지/꿀단지 네이버` 아래 글별 작업 폴더에 함께 저장한다. 프로젝트 최상위에 신규 글 작업 폴더나 임시 산출물을 늘리지 않는다. 기존 글은 해당 폴더를 재사용하며, 사이트 배포 자산은 기존 등록 절차를 유지한다.

## 주제·검색어·제목 중심 운영 (2026-09-15 사용자 승인)

이 절은 Codex의 주제·제목 조사와 자료 읽기에 관한 이전 지침보다 우선한다. 목표는 작성 시점의 독자 관심을 실제 검색 표현으로 확인하고, 저지수 블로그가 답할 수 있는 구체적인 질문으로 좁혀 제목과 본문을 연결하는 것이다.

### 선정 흐름

- 작성 시점에 독자가 궁금해할 이유를 먼저 찾는다. 최근 질문·변화·검색 신호를 확인하고 기존 글과 중복을 대조한다. 시의성이 약한 상시 관심 주제도 실제 수요 근거가 있으면 가능하되 그 성격을 밝힌다. 최근 게시물이라는 이유만으로 관심이 많다고 판단하지 않는다.
- 주제를 독자가 실제 입력하는 핵심 검색어로 바꾼다. 자동완성·연관검색어와 실제 질문에서 연결되는 표현을 수집한다. 주제와 검색어를 고정 목록이나 이전 사례로 한정하지 않는다.
- 핵심 검색어와 관련 표현을 독자의 하나의 질문으로 연결해 제목 아이디어를 만든다. 연관어를 많이 나열하는 대신 대상·상황·답변 범위가 일치하는지 판단한다. 임의로 만든 조합과 실제 관찰된 검색 표현을 구별한다.
- 유력한 조합부터 해당 채널의 실제 검색결과와 답변 본문을 비교한다. 제목마다 새로 조사하지 않고 같은 검색 의도의 후보는 근거를 공유한다. 검색어 수를 일률적으로 두 개로 제한하지 않는다. 프로그램의 서로 다른 검색어 최소 조건은 비교의 하한이며 탐색의 상한이 아니다.
- 확정 제목이 약속한 질문과 답변 범위를 본문의 기준으로 삼는다. 도입에서 핵심 답을 제시하고 소제목·설명·근거를 그 답에 연결한다. 넓은 주제의 일반 정보로 본문을 채우거나 제목에 없는 관심사로 확장하지 않는다.

### 조사 범위와 종료

- 여러 주제 후보를 모두 본문 수준으로 조사하지 않는다. 시의성·독자 질문·중복 여부로 먼저 추리고 유력 후보부터 보완한다. 이미 받은 주제·제목 선택은 유지한다.
- 주제·제목 단계에서는 실제 질문, 검색 표현, 경쟁 답변과 차별화할 범위를 확인한다. 제목의 건강 주장과 기존 검사에 필요한 공인 근거는 확인하되, 본문에서 쓸 모든 수치·기간·예외까지 미리 수집하지 않는다.
- 실제 질문과 검색 표현이 확인되고, 기존 글과 구분되며, 경쟁 답변과 비교해 작성할 범위를 설명할 수 있고, 현재 단계의 필수 검사가 통과하면 후보를 제시한다. 완전한 빈집을 찾으려고 검색을 계속하지 않는다.
- 부분 실사가 가능한 제목 비교는 검색어별 접근 가능한 주요 본문 3개부터 확인한다. 표본 수와 미열람 범위를 표시한다. 자료 부족·답변 충돌·검색 의도 불일치로 판단이 달라질 때만 추가한다. 주제 연구의 전체 검토 등 기존 프로그램이 요구하는 범위를 부분 실사로 통과 처리하지 않는다.
- 제목 확정 후 실제 본문의 주장별로 공인 원문·최신성·적용 조건·예외를 검증한다. 출처 수를 채우기 위한 검색을 하지 않으며 부족하거나 충돌하는 주장만 추가 조사한다. 확인할 수 없는 주장은 제외하거나 한계를 밝힌다.
- 소요시간과 사용량 절감률을 보장하지 않는다. 시간 절약을 위해 미확인을 확인 완료로 기록하지 않는다.

### 단계 간 자료 인계와 추가 조사 (2026-09-15 사용자 승인)

- 주제 조사부터 제목 선정·본문 작성·검수까지 기존 자료를 먼저 확인한다. 단계가 바뀌었다는 이유만으로 검색을 다시 시작하지 않는다. 필요한 질문과 저장된 근거를 대조하고, 부족한 근거·상충하는 설명·달라진 대상이나 조건·최신성 재확인이 필요한 부분만 추가 조사한다.
- 작업 폴더의 `source_notes.md`를 집필용 근거의 단일 요약으로 유지한다. 주제·선택 제목과 검색 의도, 본문에서 답할 질문, 질문별 핵심 주장과 출처 URL 또는 기존 근거 ID, 자료 날짜·실제 확인 시점, 적용 조건·한계, 사용할 본문 위치, 미확인 사항을 짧게 연결한다. 제목이나 본문 구성이 미정인 항목은 미정으로 두고 확정 후 필요한 부분만 갱신한다. 고정 예문이나 글 구조를 강제하지 않는다.
- 검색어·순위·경쟁 판단·원문 증거는 기존 해당 기록을 유지하고 위 요약에서 참조한다. 같은 근거를 단계별 문서에 복제하거나 원문 전체를 매번 읽지 않는다. 요약의 의미나 조건이 불명확할 때만 연결된 원문의 해당 구간을 다시 읽는다.
- 브라우저에서 확인한 자료도 한 조사 묶음을 마칠 때 기존 기록에 URL·실제 확인 시점·관련 내용·한계를 저장한다. 단계 전환이나 사용자에게 결과를 보고하기 전에 저장 여부를 확인하여 대화·도구 기록에만 남기지 않는다. 확인하지 못한 자료와 저장이 끝나지 않은 자료를 완료로 표시하지 않는다.
- 채널별 검색 노출과 연관검색어는 각각 확인하되, 유효한 공통 사실 근거와 동일 문서의 본문 검토는 공유한다. 제목 표현만 바뀌고 검색 의도·대상·답변 범위가 같으면 기존 조사를 재사용한다. 범위가 바뀌면 영향을 받는 질문만 추가 확인한다.
- 집필 시작 시 선택 제목이 약속한 질문과 근거 요약을 대조한다. 필요한 답과 근거가 충분하고 해당 단계의 필수 검사를 통과하면 작성한다. 출처 수를 늘리기 위한 조사나 해결된 질문의 반복 검색은 하지 않는다. 건강 수치·검사 조건·의학적 판단의 근거와 적용 한계 검증은 유지한다.
- 최신성·캐시 유효기간은 기존 검사 조건을 따른다. 기간이 지난 자료는 필요한 현재 유효성이나 검색 노출을 재확인하며, 원래 조회 시각을 덮어써 새 조사처럼 보이게 하지 않는다.
- 사용자 선택과 진행 단계는 `codex_workflow.json`을 기준으로 요약 상태를 맞춘다. 근거 파일을 수정하면 연결된 해시와 완료 기록은 기존 검사·기록 절차로 갱신하고 영향을 받는 단계만 재검사한다. 상태 파일을 직접 고쳐 통과시키거나 이미 받은 사용자 선택을 다시 요청하지 않는다.

### Python 자료 인계 검사 (2026-09-15 사용자 승인)

- `research`, `naver_titles`, `google_titles`, `draft` 단계는 작업 폴더의 `codex_reuse/{stage}.json`에 기존 자료 검토와 질문별 처리 계획을 기록한다. 연결된 실행 경로의 단계 진입과 새 완료 기록에서 검사한다.
- 선택 제목·검색 의도, 검토한 파일의 경로·SHA-256·실제 발췌문을 기록한다. 질문마다 재사용(`reuse`), 추가 조사(`additional`), 제외(`exclude`)를 구분한다. 추가 조사는 부족·충돌·범위 변경·최신성·채널별 검색결과 확인 중 실제 이유를 남긴다.
- 완료 시 질문별 답·한계·근거가 필요하며 본문 단계에는 사용할 본문 위치도 기록한다. 인계 기록과 연결된 근거 파일은 완료 기록의 검증 대상에 포함한다.
- `reuse_guard.py`의 `init`은 미완성 양식 생성, `ref`는 파일 해시·발췌문 확인, `check`는 기록 검사에 사용한다. `check --complete`로 완료 조건을 검사한다. 빈 양식 생성만으로 검토를 완료 처리하지 않는다.
- 이전 완료 기록은 소급 취소하지 않되 새 보호 단계의 완료 기록에는 인계 자료를 누락할 수 없다. 이 장치는 기록·파일의 일치와 단계 조건을 검사하며 모든 브라우저 호출을 차단하거나 사실·의미의 정확성을 보장하지 않는다.

### Python 최신성 검사 (같은 날 사용자 추가 요청으로 구현)

`python codex_tools/freshness_guard.py --work-dir "작업 폴더"`를 실행한다. `freshness_review.json`과 실제 검색 결과/원문 확인 기록이 없거나 조건을 충족하지 못하면 종료 코드 2로 차단한다. 기본 빈 양식은 `codex_tools/freshness_review.template.json`이며 작업 폴더에 복사한 뒤 실제 확인 결과만 기입한다.

- `checked_on`: 한국 시간의 오늘 날짜. `searches`: 고유 `id`, 실제 `query`, `url`, `searched_on`, `purpose`. `recent_discovery`에는 `channel`, `from`(두 달 전 1일), `to`(오늘)를 기록한다. 구글 최근 자료 검색은 필수다. 과거 자료의 변경·반박 검색은 `validity_check`와 `result`, 현재 순위 관찰은 `current_serp`로 구분한다.
- `sources`: 고유 `id`, `title`, `url`, `role`(fact/reader_question/competitor), `accessed_on`, `published_on`, 필요시 `updated_on`. 날짜를 찾지 못하면 `date_status: unknown`으로 기록한다. 날짜 확인 문구는 `date_evidence`에 넣는다. 수정일로 최신성을 판단하려면 `substantive_update: true`와 실제 수정 내용 `update_note`가 필요하다.
- 과거/날짜 미확인 자료에는 `exception_reason`이 필수다. 사실 근거와 독자 질문은 `validity_search_id`와 `validity_note`로 현재 확인 검색에 연결한다. 오래된 경쟁 문서는 `current_serp_search_id`로 현재 노출 확인에 연결한다. 최신 문서만 남겨 경쟁을 낮추어 보이지 않는다.
- 각 검색/자료 행에 작업 폴더 내 `evidence_file`, 파일의 SHA-256인 `evidence_sha256`, 그 파일에서 실제 확인 가능한 `evidence_excerpt`를 넣는다. 원문 전체를 불필요하게 복제하지 말고 날짜·출처·관련 구간의 확인 기록을 남긴다. `claims`에는 본문 핵심 주장 `text`와 사실 근거 `source_ids`를 연결한다.
- 새 리서치 완료 기록, 제목 수집·보고서 생성 및 완료 기록, 본문 시작 검사, 등록 함수, 검수·발행 완료 기록에서 필수 호출한다. 기존 완료된 제목 선택을 소급 취소하지 않지만 진행 중인 글도 본문 진입 전에 검사한다. `workflow_guard.py check --stage draft`가 본문 시작 명령이다. 해시 대상에는 최신성 JSON과 연결된 확인 기록도 자동 포함한다.
- 파일 누락, 잘못된 검색 기간, 날짜·출처·주장 연결 누락, 미래 날짜, 확인 기록 변조, 과거 자료 사용 이유/유효성 누락은 차단한다. 기존 '24시간 내 조회' 검사도 유지한다.

이 검사는 **저장된 검색·날짜·예외·근거 연결 기록**을 확인한다. 검색과 원문 조회 자체를 자동 수행하거나 모든 본문 주장을 자동 추출하지는 않는다. 출처 날짜의 진위, 검색 기록이 실제 수행됐는지, 원문이 주장을 뒷받침하는지는 AI가 실제 자료와 대조해야 한다. 임의 채팅·외부 실행을 차단하는 장치라고 설명하지 않는다.

## 실행 원칙

- 기존 주제 선정과 3+3+4 제목 구성을 유지하며, 이후 순서는 위 '본문 먼저, 이미지 나중' 개정을 따른다.
- 제목은 두 채널 모두 공백·문장부호 포함 40~60자다. 기존 길이 상한/하한에 추가하는 조건이다.
- 기존 제목 검사 함수와 검색 수집기를 title_adapter.py에서 호출한다. 자체 문법 검사기나 검색 엔진을 다시 만들지 않는다. 실행 로그만 글 작업 폴더에 격리한다.
- 기존 Git 채점식은 legacy_score.py에 그대로 보존해 사용한다. 이는 **규칙에 따른 비교 점수**이며 검색량/순위 확률을 뜻하지 않는다. 현재 공용 파일에서 점수를 제거한 변경은 되돌리지 않는다.
- 조사가 확인되지 않은 후보는 미확인으로 표시하고 점수/추천을 주지 않는다. 확인된 후보 안에서 경쟁 강도 → 직접 답변 비중 → 기존 문구 점수 순으로 최대 3개를 추천한다. 숫자·따옴표 가점이 경쟁 판단보다 앞서지 않는다. 근거 없는 추천 수를 채우지 않는다.

## 제목 선정: 일괄 수집 → 필요한 확인 → 표 한 번

제목 비교에서는 실제 연관검색어/자동완성 출처와 접근 가능한 경쟁 본문을 사용한 부분 실사를 허용한다. title_review에 상대적 경쟁 판단과 검토 시각을 기록하고, 본문 확인 수/수집 문서 수 및 미확인 범위를 출력한다. 프로그램의 최소 3개 본문 조건은 충분한 표본이나 사실 검증을 보증하지 않는다. 전체 본문 실사 및 수요·의학 근거 검증 완료(evidence_complete)와 제목 비교 가능(comparison_ready)을 구분한다. 검색량 수치나 경쟁 부재를 만들어 내지 않는다. 추천 3개는 공략 검색어가 중복되지 않게 제시한다. 선택 후 본문 작성의 기존 사실 검증은 유지한다.

1. 선택한 주제의 네이버/구글 연관검색어·자동완성을 기존 수집기로 먼저 조회한다. 실제 출처 URL·조회 시각·표현을 해당 채널 related_keywords.json에 저장하고 자료 유형을 구분한다. 자동완성 출현을 검색량 수치로 취급하지 않는다. 그 검색 표현 중 경쟁이 상대적으로 약한 영역을 확인하고, 연관 단어를 자연스럽게 조합해 기존 3+3+4 방식의 제목 10개를 만든다. 임의로 만든 표현을 실제 연관검색어라고 보고하지 않는다.
2. 기존 naver_candidates.json/google_candidates.json의 후보 배열을 사용한다. 추가 필드는 **search_queries 배열 10개**뿐이며 제목 순서와 일치시킨다. 제목별 intent_reviews, editorial_pick, recommendation_reason을 중복 작성할 필요는 없다.
3. `python codex_tools/title_adapter.py --work-dir "작업 폴더" --channel naver`를 한 번 실행한다(구글은 google). 기존 수집기를 호출하고 naver_serp_audit.json/google_serp_audit.json에 후보별 결과를 저장한다.
4. 수집된 자료에서 경쟁 문서와 답변 빈틈을 확인한다. 같은 검색어는 한 번만 수집하며, 24시간 내 검토된 동일 채널·검색어 근거는 기존 캐시로 재사용한다. 저장한 시각을 새 조회 시각으로 꾸미지 않는다.
5. 확인하지 못한 후보는 추가 조사로 남기고, 유망한 후보의 부족한 근거부터 보완한다. 자동완성·문서 수만으로 블루오션을 확정하지 않는다. 이미 확인한 공통 출처/문서는 관련 후보에서 재사용하며 제목마다 같은 문서를 반복 조사하지 않는다.
6. `python codex_tools/report_guard.py build --work-dir "작업 폴더" --channel naver`로 **후보 제목·글자 수·공략 검색어·규칙 점수·경쟁도·실사 근거 표와 추천 최대 3개**를 생성한다. 사용자에게는 표와 짧은 추천 근거를 바로 제시한다. 같은 검색어를 공유하면 표에서 드러나도록 한다.

근거 보완은 실제 수집 파일의 기존 review 구조를 사용한다. 별도의 긴 분석 보고서를 계속 추가하지 않는다. 제목 제안에서는 본문 수준의 의학 설명·출처 해설을 길게 출력하지 않는다. 본문 사실 검수는 기존 본문 단계에서 수행한다.

**실행 함수 안의 필수 검사:** title_adapter.collect는 네트워크 수집 전에 현재 단계와 실제 연관검색어 자료를 검사한다. report_guard.build_report는 보고서 파일을 쓰기 전에 단계와 후보별 근거를 검사한다. 별도의 check 명령을 빼먹어도 이 실행 경로의 선행 검사는 생략되지 않는다. 후보의 실제 연관검색어 파일도 완료 기록의 필수 해시 대상이다.

이 장치는 위 Python 실행 경로에서 실제 수집·파일 생성·등록 호출을 차단한다. 임의의 외부 프로그램 실행이나 채팅·이미지 도구 호출 자체를 통제하는 OS/앱 보안 장치는 아니다. 기존 Antigravity의 단계 검사도 호출되는 경로 안에서 적용되는 방식이다.

이 검사는 Python 실행 경로와 답변 파일을 검사하며 Codex 채팅 전송 자체를 가로채지는 않는다. 의미상 적합성과 근거의 사실 여부는 실제 자료와 대조한다. 단순 형식 통과를 전체 운영 검증으로 설명하지 않는다.

## 사이트 등록까지 이어지는 집필 (2026-09-15 사용자 지시)

구글 본문은 처음부터 기존 사이트 데이터 형식의 post_data.json(title, slug, category, desc, date, thumb, bodyHtml, references, faqs, isEditorPick=false)에 작성한다. 별도 미리보기 HTML만 만들고 등록을 다음 요청으로 미루지 않는다. 텍스트 초안과 이미지 승인은 기존 순서를 유지하며, 승인 전 이미지를 생성하지 않는다. 초안의 이미지 경로는 계획값으로 두고 승인 후 실제 파일로 채운다. 네이버 원고는 독립된 문체·구성을 유지한다.

이미지 배치 후 assembly 기록을 완료하고 `python codex_tools/site_pipeline.py --work-dir "실제 작업 폴더"`를 실행한다. 이 명령은 기존 등록 엔진의 검사를 유지하면서 실제 DB 등록, 사이트 빌드, 로컬 사이트 검사, 원고·사진·생성 페이지 대조, validation 기록까지 이어서 수행한다. 기록만 수동으로 만들어 완료 처리하지 않는다. 사이트에 생성된 posts/<slug> 페이지를 사용자에게 제공하고 화면 확인 결과는 별도로 정직하게 보고한다. 원격 배포는 기존 사용자 발행 승인 단계에서 수행한다.

Python은 신규 draft 기록에 사이트용 원고가 없는 경우, validation 기록에 실제 사이트 등록 증거가 없는 경우 완료를 차단한다. 기록 후 원고·사진·사이트 결과가 달라지면 validation으로 복귀한다. 예전 초안 기록은 유지하되 현재 글도 등록 완료 검사를 적용한다. 등록 절차를 매번 다시 조사하지 말고 이 실행 경로를 사용하며, 오류가 난 부분만 확인한다. 이 검사는 연결된 Python 실행 경로에 적용되며 임의의 도구 호출이나 채팅 자체를 통제하지는 않는다.
### 등록 연결 변경의 재발 방지 (2026-09-15)
- 저장 형식이나 경로를 변경할 때에는 기존 증거를 그대로 둔 실제 작업으로 `register_post.py --work-dir "작업 폴더" --post-file post_data.json --image-dir images --check-only`를 실행한다. 이 검사는 쓰기 없는 등록 전 점검이며 실제 등록 성공으로 보고하지 않는다.
- 연결 실패 시 오류가 난 입력 경로·형식부터 수정한다. 게이트 통과를 목적으로 리서치 원본에 보고서를 덧붙이거나 과거 승인·완료 기록을 일괄 재작성하지 않는다. 원본 변경이 실제로 필요한 경우에만 해당 단계의 정상 재검증 절차를 적용한다.
- 수집 캐시와 검토 완료 근거를 구분한다. Codex 등록은 완료된 research 기록의 해시와 일치하는 지정 근거를 읽고, 기존 근거 내용·날짜·주제 검사도 그대로 실행한다. 변경·누락된 근거는 차단한다.
- 자동화 수정 완료는 단위 검사, 실제 작업의 등록 전 검사, 실제 등록·빌드 결과를 구분해 보고한다. 사용자에게 사이트에서 볼 수 있다고 말하려면 실제 생성 페이지 링크를 제공한다. 공개 주소 반영은 배포 후 별도로 확인한다.
### 구글 본문 서식 단일화 (2026-09-15 사용자 지시)
구글 원고는 기존 사이트의 bodyHtml 서식으로 직접 작성한다. 별도 스타일의 미리보기 HTML을 만든 뒤 변환하는 경로는 사용하지 않는다. 미리보기는 빌드된 실제 posts 페이지 하나만 제공한다. 핵심 요약 카드 lead-quote-card(직접 인용 선택), 제목·목록이 있는 toc-box, 소제목 바로 아래 post-img-wrap 사진과 figcaption을 유지한다. Codex 등록 전 validate_body_style 검사를 반드시 통과한다. 검사 통과를 브라우저 시각 검수 완료로 표현하지 않는다. 서식 변경은 원고에 적용해 빌드하며 생성 HTML만 임시 수정하지 않는다.
## 주제 후보 선정 간소화 (2026-09-16 사용자 지시)

이 절은 주제 선택 전 상세 조사를 요구하는 이전 규칙보다 우선한다.

- 주제 선택 전에는 기존 글 제목과 검색 결과 제목만으로 우선 추린다. 화면에 보이는 요약·날짜는 보조 자료로 활용하며 본문을 열지 않는다. 저장된 조사 자료를 먼저 재사용한다.
- 후보 3개와 추천 1개를 먼저 제시하고 사용자의 주제 선택을 기다린다. 독자 질문, 제목상 중복 가능성, 추천 이유와 미확인 사항을 간단히 표시하고 탐색을 종료한다.
- 이 단계의 결과는 '블루오션 후보'다. 제목만으로 검색량·저경쟁·내용 중복 없음·답변 누락을 확정하지 않는다.
- 이 사전 후보 단계는 workflow_guard.py의 정식 research 완료와 구분한다. 후보 보고 전에 research 완료 검사·기록, 상세 근거 manifest, 본문 전수 검토, 공인 출처와 내부링크 확보를 요구하지 않는다. 상태가 research여도 주제 선택 전에는 상세 조사를 시작하지 않는다. 후보 요약·검색어·URL·확인일만 글별 작업 폴더에 저장한다.
- 주제 선택 후 선택된 주제만 정식 research와 기존 제목 선정 절차로 진행한다. 경쟁 글의 핵심 문단과 필요한 공식 자료를 확인하며 탈락 후보나 이미 확인한 자료를 반복 조사하지 않는다.
- 로그인 제한 자료는 본문 미확인으로 남기고 공개 자료를 활용한다. 후보 조사를 위해 로그인을 요청하지 않는다. 미확인을 실사 완료로 기록하지 않는다.
- 이후 사실 검증·제목 선택·이미지 승인·등록·발행 조건은 유지한다. 이전의 '제목 제시 전에 대기하지 않는다'는 지시는 사전 후보 3개를 제시한 뒤 주제 선택을 기다리는 경우에는 적용하지 않는다.
