# 꿀단지 사이트 검수

Cloudflare **무료 플랜**을 사용한다. 검수 기본값은 로컬이며, 유료 서비스나 서버 작업을 추가하지 않는다.

## 실행

- `python tools/audit_site.py --local`: 읽기 전용 파일/링크 검사. 인자를 생략해도 로컬 검사만 한다.
- `python tools/deploy_site.py --check-only`: 로컬 검사와 기존 카드 검사만 수행. Git 변경·업로드·색인 요청 없이 종료한다.
- `python -m unittest discover -s tools -p test_site_audit.py`: 임시 파일과 모의 배포로 검수기의 오류 탐지/배포 차단을 검사한다.
- `node --test tools/comments_security.test.mjs`: 모의 KV로 댓글 보안 검사를 실행한다. 실제 댓글을 쓰거나 삭제하지 않는다.
- `python tools/audit_site.py --live`: 로컬 검사 통과 후 명시적으로 실서버 HTTP 검사. 페이지마다 1회 GET, 댓글 API/KV 호출 없음.

일반 `deploy_site.py` 실행은 실제 배포다. 검수 용도로 실행할 때는 반드시 `--check-only`를 사용한다.

## 자동 연결

빌드 마지막에 로컬 검사를 실행하며 실패하면 빌드 성공을 표시하지 않는다. 생성한 파일은 남으므로 실패 원인을 고친 뒤 재검사한다.
업로드 스크립트의 로컬 검사는 Git remote 변경·stage·commit·push보다 먼저 실행된다. 도구 누락, 실행 오류, 검사 실패는 배포를 차단한다. 기존 카드 검사도 유지한다.
실서버 HTTP 검사는 기존처럼 push 이후 수행한다. 그 단계의 실패는 이미 전송한 배포를 되돌리지 않는다.

## 검사 범위와 기준

- 내부 링크: 실제 파일, 폴더 목적지 오류, URL 인코딩, 쿼리, 정적 앵커 id/name. 브라우저가 정의한 `#top`은 허용한다.
- 이미지·CSS·JS·아이콘: 참조 대상 파일 존재. 필수 페이지, 문의 폼 입력란, 레지스트리와 DB 글 목록 및 썸네일도 검사한다.
- HTML의 주요 구조 태그 중첩/닫힘: HTML 파서 사용. JS 문자열이나 주석 속 태그를 실제 태그로 세지 않는다.
- 인코딩: 정상 선두 BOM 1개는 허용하며 파일은 변환하지 않는다. 중복 BOM과 잘못된 UTF-8은 실패한다. 과거 모든 BOM 실패 판정과 구분한다.
- 과거 문서의 features.js 50KB 기준은 별도 참고로 출력한다. 현재 정상 파일은 약 39KB이므로 크기를 채워 넣지 않고 DB/레지스트리/목적지 파일 대조를 기능 판정에 사용한다.
- 문의 폼은 현재 구현의 user-name/user-email/user-message를 검사한다. 문서의 과거 contactName 등과 다르다.

브라우저 레이아웃, 실제 검색·카테고리 클릭, JavaScript 실행 오류, 동적으로 생성되는 링크, CSS 내부 URL/srcset, 외부 링크, 실서버 댓글/비밀키, 새 배포 버전 반영은 이 파일 검사로 보장하지 않는다. HTTP 200도 새 버전 반영 증명이 아니다. 별도 확인 결과를 통과/실패/미확인으로 보고한다.
