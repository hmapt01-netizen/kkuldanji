# 댓글 보안과 관리자 비밀번호 운영

이 변경은 로컬 코드 수정이다. Cloudflare 배포 및 실제 기능 검증 전에는 실사이트 적용 완료로 보고하지 않는다. 무료 플랜을 유지하며 유료 서비스나 추가 저장소를 도입하지 않는다.

## 사용 방법

- 방문자: 기존처럼 닉네임, 비밀번호(8~128자), 댓글을 입력한다. 삭제할 때 같은 비밀번호를 입력한다.
- 관리자: 관리자 화면에서 본인이 정한 비밀번호 하나로 로그인한다. 새로고침하면 다시 입력한다. 댓글 관리용 두 번째 키는 없다.
- 관리자 비밀번호를 잊으면 Cloudflare에서 새 값으로 바꾸고 재배포한다. 방문자 댓글의 삭제 비밀번호에는 영향이 없다.
- 수정 전에 작성된 댓글은 비밀번호가 공개됐을 수 있으므로 관리자만 삭제한다. 기존 댓글을 일괄 삭제하거나 데이터를 강제 변환하지 않는다.

## Cloudflare에서 한 번 설정

Pages 프로젝트 kkuldanji → 설정 → Production → 변수 및 비밀:

- 유형: 비밀(Secret)
- 변수 이름: COMMENTS_ADMIN_PASSWORD
- 값: 사용자가 정한 9~128자 비밀번호. 기억하기 쉬운 여러 단어의 긴 문장을 권장하며 다른 서비스 암호를 재사용하지 않는다. 한글도 지원하며 앞뒤 공백은 제외한다.

실제 값은 사용자가 직접 입력하고 저장한다. 채팅·Git·HTML·localStorage에 넣지 않는다. 기존 HONEYJAR_COMMENTS_KV 바인딩을 사용한다. Preview를 사용한다면 별도 환경 설정이 필요하다.

COMMENTS_PASSWORD_PEPPER와 COMMENTS_ADMIN_TOKEN은 이 버전에서 사용하지 않는다. 이전 두 항목의 미저장 입력은 취소한다. 이미 저장했다면 현재 배포 코드의 의존성을 먼저 확인한 후 정리하며 값을 읽거나 복사할 필요는 없다.

## 보호 방식

- 브라우저 Web Crypto에서 댓글마다 16바이트 무작위 salt와 PBKDF2-SHA256 600,000회로 32바이트 proof를 만든다. 서버에는 비밀번호 원문 대신 proof와 salt를 보낸다.
- proof는 비밀번호와 같은 권한을 가진 민감 값이다. HTTPS에서만 다루며 로그·응답·캐시에 남기지 않는다. 서버는 버전·salt·proof를 결합한 SHA-256 검증값만 저장한다. 저장된 검증값 자체를 삭제 요청에 재사용할 수 없다. 비밀번호 원문에 빠른 SHA-256만 적용한 설계가 아니다.
- 삭제 준비 요청은 해당 댓글의 버전과 공개 가능한 salt만 반환한다. 서버가 proof를 검증한 뒤 삭제한다. 일반 댓글 GET/POST 응답은 공개 표시 필드만 반환한다.
- 관리자 비밀번호는 HTTPS Authorization 헤더로 보내며 서버 환경 변수와 비교한다. 로그인 검사와 전체 댓글 조회·삭제 모두 서버가 확인한다. 페이지 메모리에만 유지하고 로그아웃 때 지운다. 고정 숫자 암호 및 sessionStorage 플래그 인증은 제거했다.
- Web Crypto가 없으면 평문 전송으로 우회하지 않고 안내한다. 저장 실패를 성공으로 표시하지 않는다. 기존 브라우저 캐시에서 비밀번호를 제거하고 사용자 입력을 실행 가능한 HTML로 삽입하지 않는다.

이 방식은 서버 비밀키 없이 댓글 비밀번호의 오프라인 추측 비용을 높이기 위한 클라이언트 사전 처리다. HTTPS와 브라우저 코드의 무결성이 필요하며 XSS, 악성 확장, 탈취한 proof의 재사용까지 해결하는 것은 아니다.

## 검증 및 배포

- 로컬: node --test tools/comments_security.test.mjs
- 사이트: python tools/audit_site.py --local 및 python tools/deploy_site.py --check-only
- 두 API 파일, 댓글 JS, 관리자 HTML/JS, 버전이 변경된 HTML/템플릿을 함께 배포한다. 설정 저장 후 재배포가 필요하다.
- 실배포: 테스트 댓글 등록 → 공개 응답의 민감 값 미노출 → 틀린 비밀번호 거부 → 올바른 비밀번호 삭제 → 관리자 로그인/조회/삭제를 확인한다. 실독자 댓글을 시험용으로 삭제하지 않는다.
- 실제 Cloudflare CPU 사용량 및 모바일 브라우저 체감 시간은 배포 후 별도 확인한다. 로컬 통과만으로 무료 런타임 동작까지 보장하지 않는다.

## 남아 있는 한계

- Workers 무료 CPU 제한을 고려해 무거운 PBKDF2 연산은 브라우저에서 수행한다. 서버에서는 digest 비교를 사용한다. 실제 실행 시간이 제한 안에 드는지는 런타임에서 확인해야 한다.
- 기존 KV의 글별 배열 읽기/쓰기 구조는 동시 갱신 충돌과 전파 지연 가능성이 있다. 이번 변경은 원자적 저장으로 바꾸지 않았다. 무료 KV 할당량 및 같은 키의 쓰기 제한도 유지된다.
- 변경/관리자 요청에는 IP당 1분 20회, 실행 인스턴스 메모리 기반 제한을 추가했다. 인스턴스 교체·분산 접속에서 초기화될 수 있으므로 완전한 무차별 대입/도배 방어가 아니다. 분산 제한이나 봇 검증은 별도 설계가 필요하다.
- 정적 관리자 페이지 HTML 자체는 공개된다. 댓글 서버 권한을 검사하는 수정이며 관리자 화면의 다른 기능·외부 API 전체를 감사한 것은 아니다.
- 취약한 기존 API로 롤백하면 비밀번호 공개와 관리자 우회가 다시 발생한다. 문제가 생기면 댓글 쓰기를 중지하고 수정 버전을 적용한다.
- tools/deploy_site.py는 기존 .gitignore 대상이므로 로컬 운영 스크립트의 점검 개선은 Git 복원에 포함되지 않는다. 배포 전 백업 범위를 구분한다.
