# 🧠 사람이 쓴 듯한 전문 블로그 마스터 글쓰기 스킬 (Master Blog Skill)

🚨 **[최우선 필수 이행 수칙]**: AI는 이 스킬 문서의 모든 지침을 숙지하고, 리서치 ➔ 제목 도출 ➔ 본문 생성 ➔ 깨짐 없는 HTML 서식 출력까지 단 한 단계도 건너뛰지 않고 엄격히 진행한다.

---

# 📌 1. 「혀니의 꿀단지」 표준 제목 공식 (Mandatory Title Formula)

블로그의 주제가 다양하더라도 제목 구조를 일관되게 통일하여 검색 노출과 독자 신뢰도를 동시에 확보한다:

$$\text{[메인 검색어]} \quad\longrightarrow\quad \text{[구체적인 정보 (숫자/맥락)]} \quad\longrightarrow\quad \text{[보조 검색어 (롱테일 유입)]}$$

* **표준 공식**: `[메인 검색어], [구체적인 정보]와 [보조 검색어]`
* **대표 예시**: `오나라 식단 공개, 51세 47kg 관리법과 50대 근력 운동`
  * **메인 검색어**: `오나라 식단 공개` (검색량이 가장 많은 핵심 타겟)
  * **구체적 정보**: `51세 47kg 관리법과` (클릭률 CTR을 높이는 구체적인 팩트 수치)
  * **보조 검색어**: `50대 근력 운동` (연관 롱테일 검색 유입 확장)

# 🔗 2. 서사 직결 원칙 (제목 ➔ 첫 문단 ➔ 소제목)

검색 엔진의 **주제 일관성(Relevance)**을 극대화하기 위해, 첫 문장부터 제목의 핵심 키워드를 자연스럽게 받아친다:

* **[제목]**: `오나라 식단 공개, 51세 47kg 관리법과 50대 근력 운동`
* **[첫 문단 시작 문장]**: 
  `"배우 오나라가 SNS를 통해 다양한 샐러드 식단을 공개하면서 50대 식단 관리에 대한 관심도 높아지고 있습니다."`
* ➔ **효과**: 제목에서 클릭한 독자가 첫 줄에서 즉시 답을 얻어 이탈률(Bounce Rate)이 낮아지고 체류시간이 대폭 증가함.

# 🛡️ 3. 신뢰도 & E-E-A-T 5대 핵심 작성 수칙

### ① 사실 → 관찰 → 해석 3단계 구조 (Fact-Based Transparency)
* 인물(연예인 등)이나 사례를 다룰 때, **실제 공개된 팩트**와 **일반 정보**를 엄격히 분리한다.
  * ❌ **[단정적 비약 금지]**: "오나라는 굶는 다이어트를 절대 하지 않는 철학을 가지고 있습니다."
  * ⭕ **[사실 기반 관찰 서술]**: "오나라가 최근 공개한 식단을 보면 무조건 식사량을 줄이기보다는 채소와 단백질, 복합 탄수화물을 함께 구성한 식사를 선택한 모습이 눈에 띕니다."

### ② 일반 운동/건강 정보 분리 및 [안내] 박스 필수 삽입
* 특정 인물이 직접 공개한 루틴이 아닌, 일반적인 추천 운동/건강법을 제시할 때는 반드시 명확한 안내 문구를 표기한다.
  * **필수 안내 서식**:
    `[안내] 아래 운동은 [인물]이 직접 공개한 운동 루틴을 그대로 옮긴 것이 아니라, [연령/상황] 체형 관리에 일반적으로 활용할 수 있는 운동을 정리한 것입니다.`

### ③ 의학·건강학적 표현의 정확성 (과장 및 오류 차단)
* **특정 부위 감량(Spot Reduction) 오류 금지**: "허리 군살 제거" ➔ "코어 근육 강화 및 몸통 안정성 향상"
* **노화/신체 변화 단정적 표현 완화**: "50대에는 매년 근육이 빠집니다" ➔ "나이가 들수록 근육량과 근력이 감소하기 쉬워지기 때문에 꾸준한 근력 운동이 중요합니다."
* **극단적 영양소 제한 경고의 균형**: "탄수화물 끊으면 무기력증 옵니다" ➔ "탄수화물은 주요 에너지원이므로 활동량에 맞춰 적절히 섭취하는 것이 좋습니다."
* **과도한 섭취 빈도 강요 금지**: "매 끼니 단백질 필수 섭취" ➔ "단백질 식품을 식사에 적절히 활용"

### ④ 메타데이터 정직성 (가짜 조회수/통계 금지)
* 타 사이트 캡처본의 조회수(예: 249,898회)나 불필요한 매거진형 표기(읽는 시간 등)를 본문 UI에 무단 복제하지 않는다. 독자에게 혼란을 주지 않는 정직한 메타 구조를 유지한다.

### ⑤ 에버그린 콘텐츠 수명 관리
* 해가 지나도 글이 어색해지지 않도록 연도/나이의 오차를 최소화한다. (예: 구체적인 단일 나이 표기 외에도 '1974년생', '50대' 등 포괄적 키워드 병행)

# 🚫 4. 문체 & 표현 절대 금지 수칙

### ❌ 이모지(Emoji) 100% 전면 배제
* 본문, 제목, 소제목, 표, 박스, 리스트 어디에도 이모티콘/이모지(🥗, 🏋️, 💡, 🚫 등)를 절대 넣지 않는다.
* 시각적 강조가 필요할 경우 **깔끔한 숫자 배지(`01`, `02`), 대괄호(`[안내]`), 볼드체, 세련된 테두리 선**을 사용한다.

### ❌ AI 특유의 광고성 찬양 미사여구 차단
* `~를 자랑합니다`, `~빛나는 미모`, `~환상적인 바디라인`, `~선사합니다` 같은 보도자료/AI 번역투 표현 금지.
* 항상 차분하고 객관적인 관찰자 시점 유지.

### ❌ 담백한 이미지 캡션 원칙
* 이미지 하단에 반복적인 찬양 문구를 넣지 않고, 사진에 보이는 사실 그대로를 짧고 담백하게 설명한다.
  * ❌ "52세에도 군살 없는 실루엣과 탄탄한 라인을 유지 중인 배우 오나라 (출처: 인스타그램)"
  * ⭕ "배우 오나라의 일상 모습 (출처: 오나라 인스타그램)"

# 💻 5. 블로그스팟(Blogger) 100% 깨짐 방지 인라인 HTML 표준

블로그스팟은 테마 초기화 CSS(Reset CSS)와 에디터 변환 과정에서 `<style>` 태그를 무력화하므로, **모든 서식은 태그 내부에 직접 지정하는 100% 인라인 스타일(`style="..."`)**로 작성한다.

### ① 표(Table) 인라인 서식 (테두리 & 배경색 고정)
```html
<div style="overflow-x: auto; margin: 24px 0; -webkit-overflow-scrolling: touch;">
  <table style="width: 100%; min-width: 500px; border-collapse: collapse; border: 1px solid #cbd5e1; font-size: 15px; text-align: left; background-color: #ffffff;">
    <thead>
      <tr style="background-color: #f1f5f9; border-bottom: 2px solid #cbd5e1;">
        <th style="padding: 13px 15px; border: 1px solid #cbd5e1; color: #1e293b; font-weight: bold; text-align: center;">항목</th>
        <th style="padding: 13px 15px; border: 1px solid #cbd5e1; color: #1e293b; font-weight: bold; text-align: center;">내용</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td style="padding: 13px 15px; border: 1px solid #e2e8f0; font-weight: bold; text-align: center;">구분</td>
        <td style="padding: 13px 15px; border: 1px solid #e2e8f0; color: #4a5568;">설명</td>
      </tr>
    </tbody>
  </table>
</div>
```

# 🔍 6. 구글 SEO 구조화 데이터(JSON-LD) 표준

불필요한 가짜 URL(`mainEntityOfPage: example.com`)을 배제하고 구글 검색엔진이 자동으로 사이트 주소를 수집하도록 간결하고 표준적인 스키마를 탑재한다.

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "[글 제목]",
  "description": "[핵심 메타 요약]",
  "inLanguage": "ko-KR",
  "datePublished": "YYYY-MM-DD",
  "dateModified": "YYYY-MM-DD",
  "author": {
    "@type": "Person",
    "name": "[블로그/작성자명]"
  }
}
</script>
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "[핵심 질문 1]",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "[답변 내용 1]"
      }
    }
  ]
}
</script>
```
