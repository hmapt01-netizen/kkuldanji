# 꿀단지 주제 선정 에이전트

목표는 오늘 비교한 후보 중 꿀단지가 상대적으로 검색 노출을 노려볼 만한 질문을 고르는 것이다. 데이터 부족을 이유로 판단을 모두 회피하지 말고, 관찰된 사실과 편집 판단의 범위를 분명히 하면서 추천한다.

## 시작과 자료 수집

프로젝트 루트에서 실행한다. 아래 `작업폴더`는 `꿀단지 네이버/YYYY-MM-DD-주제탐색` 안의 실제 폴더로 바꾼다. 기존 파일이 있으면 이어 읽고 수집 원본을 덮어쓰지 않는다.

현재 Windows에서 `python`이 PATH에 없으면 아래 명령의 `python` 대신 `& "C:\Users\lim\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"`를 사용한다. 이 경로로 실제 실행을 검증했다. GSC 연결 의존성은 프로젝트 내부 `codex_tools/topic_agent_20261005/dependencies`에 준비되어 있으며 PC의 전역 Python 설정을 바꾸지 않는다.

```powershell
python tools/topic_opportunity.py prepare --work-dir "작업폴더"
```

- 기본으로 기존 글의 제목·설명·날짜·slug와 최근 28일 GSC 검색어/페이지 실적을 수집한다. GSC 권한·라이브러리 부족은 미확인으로 남기며 공개 검색으로 진행한다. 로그인이나 유료 API를 후보 조사 필수 조건으로 만들지 않는다.
- 네이버 공식 검색광고 API(`tools/naver_searchad.py`), 데이터랩 쇼핑인사이트(`tools/datalab_popular.py`), 도메인 분류 엔진(`tools/topic_taxonomy.py`)이 연동된 **하이브리드 발굴 엔진**입니다.
- **꿀단지 3대 공식 카테고리 체계 (홈트레이닝, 식단 & 영양, 라이프 웰니스)**:
  - `data/posts_db.json`의 실발행 38편 분류 체계와 100% 일치합니다.
  - **하이브리드 융합 엔진 (Dual Live Streams, Zero-Seed)**:
    - **스트림 A (소비/쇼핑 트렌드)**: 네이버 데이터랩 쇼핑인사이트 실시간 랭킹에서 대중이 지금 돈을 쓰거나 구매를 고민하는 실시간 핫 아이템(소도구, 영양제, 보조용품)을 수집하여 **네이버 쇼핑 커넥트(커머스 수익화)** 연계 적합도를 자동 태깅합니다.
    - **스트림 B (의학/증상/시의성 트렌드)**: 당월 캘린더 엔진(10월 환절기 일교차, 가을 비염, 독감 백신, 연말 건강검진)과 부위별 해부학/영양학 루트를 결합하고, 포털 실시간 자동완성을 통해 대중의 실제 질문형 검색어를 낚아챕니다.
  - **시드가 없을 때 (Zero-Input 자동 발굴 모드)**: 대표님이 시드를 주지 않아도, 하이브리드 엔진이 3대 카테고리별 실시간 데이터랩과 포털 자동완성, 검색광고 API를 순회하여 실제 대중 검색어와 공식 검색량을 수집합니다.
  - **비의료/상업/병원광고 100% 컷**: 대형 가전, 병원 시술(도수치료, 주사 등), 병원광고, 일반 의류/화장품 잡음을 차단하고, 기존 38편 중복을 제거한 뒤, 월 1,000~30,000회 황금 트래픽 구간 후보를 도메인별로 수집합니다.
  - **시드가 있을 때**: 명시적 관심 분야는 `--seed "검색 표현"`으로 전달하며, 검색광고 API로 실측 지표를 확보합니다.
- **기존 글과의 조화 (토픽 클러스터 & 시너지 매핑)**: 각 후보 키워드는 기존 38편 글과의 내부 링크 연결성(`calculate_synergy`)을 자동 분석하여 `synergy_posts`로 기록합니다. 단독 외딴섬 글이 아닌 기존 자산과 맞물리는 삼각편대 후보를 우선 평가합니다.
- **최종 3대 카테고리 1:1 브리핑 (1 Candidate per Category & 1 Top Pick)**:
  - 🏋️ [홈트레이닝] 1개 (소도구 안전 사용법/체형 교정 + 쇼핑 커넥트 연계점)
  - 🥗 [식단 & 영양] 1개 (영양제 복용 골든타임/기전 비교 + 쇼핑 커넥트 연계점)
  - 🩺 [라이프 웰니스] 1개 (10월 환절기/통증 감별 + 쇼핑 커넥트 연계점)
  총 3개의 최정예 후보를 실측 검색량, 쇼핑 커넥트 연계성, 기존 글 시너지 링크와 함께 보고하고, 3개 중 오늘의 잠정 추천 1개를 제안하며 사용자 선택(HARD STOP)을 대기합니다.
- 실시간 랭킹 판을 한눈에 볼 때는 `python tools/view_top_keywords.py --cat all` (특정 카테고리는 `--cat hometraining`, `--cat diet`, `--cat wellness`)를 실행합니다.

## 후보를 찾고 좁히는 방법

1. 네 경로를 함께 살핀다: 꿀단지 5대 핵심 도메인(홈트레이닝, 통증/감별, 검진/수치, 식단/영양, 계절웰니스 전원 동등 1순위)의 네이버 공식 검색량 실측치, 우리 사이트의 실제 GSC 반응, 현재 검색에서 관찰되는 구체적 질문(자동완성), 기존 글과의 토픽 클러스터 시너지. 반응이 있는 특정 분야만 반복하지 않고 5대 전 영역을 균형 있게 비교한다. 뉴스 노출을 검색수요 급증으로 바꾸지 않는다.
2. 약 10개는 탐색 예산의 기본값이다. 의미 있는 후보가 적으면 억지로 채우지 않는다. 먼저 독자의 질문과 공략 검색 표현을 정한다. 완성형 제목은 이후 사용자 선택 단계에서 만든다.
3. 기존 제목·설명으로 중복 가능성과 시너지 링크를 확인한다. 같은 답이면 기존 글 보완, 다른 조건·질문이면 새 글 후보로 검토한다. 단어 일치만으로 중복 확정, 게시 후 며칠 지났다는 이유로 재작성 허용을 하지 않는다. 새 글 작성 시 함께 묶을 수 있는 기존 글(시너지 글) 2~3편을 반드시 확인한다.
4. 유망한 질문의 네이버·구글 검색 화면을 각각 확인한다. 기본적으로 상위 일반 문서 5개 안팎의 제목·요약·URL·화면 위치를 기록하되 수집 범위를 밝힌다. 광고·쇼핑·지도·영상·공식 답변 영역도 관찰하면 기록한다. 일반 블로그가 없다는 이유만으로 진입 가능성이 높다고 판단하지 않는다.
5. 사용 도구의 일반 웹 검색 결과를 네이버/구글 실제 상위 순위라고 부르지 않는다. 정확한 포털 검색 화면을 못 봤다면 `web_search` 자료로 기록하고 해당 채널은 `explore`로 둔다. 캡차/빈 결과는 실패이지 저경쟁 증거가 아니다.
6. 제목·요약만 보고 내용의 답변 누락을 확정하지 않는다. 현재 기존 순서인 주제 선택 → 네이버 제목 선택 → 구글 제목 선택 → 리서치를 유지한다. 원문 열람은 리서치에서 기존 접근 검사를 따른다. 이번 주제 탐색을 정식 research 완료로 꾸미지 않는다.
7. 관찰한 제목의 질문 적합성, 자료 형식의 적합성, 수요 단서, 기존 자산 시너지, 추가할 답변 가치와 작성 부담을 함께 비교한다. 단어 가점·임의 확률·검색결과 총수/블로그 수 비율로 순위를 만들지 않는다. 건강 관련 답변 가치가 불확실한 경우 리서치에서 확인할 조건을 적는다.

## 판단 파일과 보고

파일 구조와 추가 관찰 기록법은 [근거 기록 규격](references/review-schema.md)을 필요한 때 읽는다.

- 후보의 `origin`은 `observed` 또는 `hypothesis`. source_ids로 관찰 출처를 연결한다.
- 후보별로 독자 질문, 기존 글과의 관계, 추가할 가치, 사이트 적합성을 작성한다. `action`은 새 글(new), 보완(update), 탐색(explore) 중 선택한다.
- 채널별로 실제 화면 근거가 있으면 비교 후보(compare), 불확실하지만 검토 가치가 있으면 탐색 후보(explore), 상대적으로 불리하면 보류(hold)로 판단하고 이유·미확인을 작성한다. compare는 낮은 경쟁이나 노출 성공을 뜻하지 않는다.
- `recommendations`에 후보 ID 최대 3개를 순서대로 적는다. 첫 항목이 잠정 추천 1개다. `comparison_reason`에 왜 차선 후보보다 먼저 쓸 만한지, 추천을 바꿀 반증 조건까지 적는다. `search_limits`에는 못 확인한 범위를 적는다. 충분한 근거가 없는 상황에서도 탐색 추천은 가능하다.

```powershell
python tools/topic_opportunity.py report --work-dir "작업폴더"
```

생성한 `topic_report.md`의 후보·추천·근거·한계를 사용자에게 간결하게 보고하고 실제 주제 선택을 기다린다. 수집기는 자동 조사 완료나 선택 승인을 만들지 않는다. 선정된 후보만 기존 제목·리서치·작성 절차로 인계한다. 원문 확인 후 답변 가치가 없거나 제목 약속을 뒷받침할 수 없다면 범위 수정/보류 이유를 보고한다.

## 발행 결과를 다음 추천에 반영

다음 주제 선정 때 이전 `topic_report.md`와 `topic_outcomes.jsonl`을 활용한다. 기존 판단을 소급 수정하지 않는다. 발행 후 약 2/4/8주에 검토할 수 있으나 별도 자동 일정은 만들지 않는다.

```powershell
python tools/topic_opportunity.py feedback --work-dir "작업폴더" --candidate "후보ID" --page "실제 발행 URL" --note "발행일·검토 이유·비교 한계"
```

최근 28일 해당 페이지의 GSC 검색어 결과를 원래 추천 기록 해시와 함께 추가 기록한다. 성공한 적이 없는 조회를 0으로 기록하지 않는다. 발행 경과일·색인 여부·기기·계절·순위 변화가 다른 자료를 곧바로 같은 조건으로 비교하지 않는다. 클릭률 하나로 제목 원인을 확정하거나 노출 없음으로 수요 없음을 단정하지 않는다. 네이버 성과는 별도 자료로 확인하며 구글 성과를 대입하지 않는다.

## 운영 경계

외부 발행·사용자 선택·제목 승인·이미지 승인은 이 스킬이 대신하지 않는다. 설치된 도구 이름만 사용하고, 결과 URL·시각·발췌를 실제 조회에서 기록한다. 검색어에 특정 단어가 있거나 JSON 검사를 통과했다는 사실을 경쟁 검증으로 보고하지 않는다. 코드·지침의 오류는 사실대로 밝히고, 일반 콘텐츠 작업 중 임의로 검사를 우회하거나 과거 기록을 성공으로 바꾸지 않는다.
